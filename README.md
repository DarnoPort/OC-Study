# IGOR — OS Development Study

Репозиторий служит внешней памятью и справочником учебного проекта IGOR, чтобы продолжать обучение в новых чатах без повторного пересказа.

## Проект
- **Название:** IGOR.
- **Цель:** учебная собственная ОС с постепенным освоением принципов ОС.
- **Целевая архитектура:** x86, 32-bit. x86-64 отложена.
- **Michael OS:** отдельный предыдущий проект; использовать как референс, не как целевую ОС.
- **Среда:** Ubuntu доступна и установлена; пользователь подтвердил, что инструменты уже скачаны. Точный набор IGOR ещё проверим на практике.

## Правила обучения
1. Понимание важнее скорости; идти небольшими шагами.
2. Синтаксис C объяснять с нуля, учитывая основной прежний опыт пользователя в Python.
3. Формат: теория → механика → небольшой пример → мягкая проверка → практика → recap.
4. Не выдавать большие листинги без объяснения назначения.
5. Различать «обсуждено» и «подтверждено ответами/практикой».
6. При затруднениях объяснять спокойно; ошибки локализовать, не переписывать проект без причины.
7. После каждого урока обновлять этот README.

## Учебный прогресс

### Урок 0.1 — ОС и загрузка
**Статус:** базовые идеи частично усвоены; углубление потребуется.
- CPU выполняет машинные инструкции и может работать без ОС.
- ОС — привилегированное системное ПО, управляющее ресурсами и предоставляющее сервисы.
- Упрощённая цепочка: CPU reset → BIOS/UEFI → загрузчик → ядро.
- Загрузчик подготавливает загрузку и передаёт управление ядру.
- C-код напрямую не исполняется CPU: компилятор создаёт машинный код; linker связывает объектные файлы; загрузочный механизм подготавливает запуск.
- Пользователь по существу различил роль CPU, ОС, загрузчика и ядра. Компиляция/linking/образ пока не закреплены практикой.

### Урок 0.2 — Инструкции, регистры и память
**Статус:** начальное понимание подтверждено ответами.
- Машинные инструкции, регистры EAX/EBX/ECX/EDX/ESP/EBP, `mov`, `add`.
- EIP содержит адрес следующей инструкции; переходы могут изменить поток выполнения.
- RAM моделируется как адрес → содержимое. `mov eax, 0x2000` загружает число/адрес, а `mov eax, [0x2000]` читает память по адресу.
- `0x` — шестнадцатеричная запись; скобки `[]` в Assembly означают обращение к памяти.
- Пользователь правильно решил примеры с регистрами, адресами RAM и различием immediate vs memory operand.

### Уроки 0.2.1–0.2.2 — Основы C и указатели
**Статус:** базовое понимание подтверждено; закреплять по мере практики.
- `int x = 123;`: тип, имя, присваивание, значение; тип влияет на интерпретацию/размер объекта.
- `&x` получает адрес; `int *p` — указатель; `p` хранит адрес, `*p` обращается к объекту по адресу.
- `*p = 100` записывает значение в исходный объект через указатель.
- `int p = x` копирует значение, а `int *p = &x` хранит адрес.
- Пользователь верно определил значения в задачах с указателями. Ранее путал изменение указателя с изменением объекта; отдельно закреплено: `p = &y` меняет адрес в p, но само x не изменяет.

### Урок 0.3 — Функции, стек, `call` и `ret`
**Статус:** базовое понимание подтверждено ответами; подробности calling convention отложены.
- Разобраны функции C, параметры, `return`, стек как LIFO, ESP как адрес вершины стека, EBP как ориентир stack frame в упрощённой модели.
- `push` уменьшает ESP на 4 байта в 32-битном примере; `pop` извлекает верхнее значение.
- `call` сохраняет адрес возврата в стеке и передаёт выполнение функции; `ret` извлекает адрес возврата и загружает его в EIP.
- Пользователь верно объяснил LIFO аналогией с тарелками, правильно определил результаты записи через указатель и ESP после push/call (`0x7FFC` при исходном `0x8000`).
- Уточнено: при `call` EIP переходит на функцию; адрес инструкции после call сохраняется для возврата. `ret` берёт адрес из стека, а не из EIP.

## Текущая точка остановки
Урок 0.3 завершён на базовом уровне. Пользователь различает значение/адрес/содержимое, понимает базовые указатели, LIFO, ESP и общую роль `call`/`ret`. Не считать стек, соглашения вызова и детали машинного исполнения полностью освоенными.

**Следующий шаг: урок 0.4 — первая практика в Ubuntu.** Проверить окружение и доступность GCC/NASM (не предполагать без проверки), написать и скомпилировать небольшую программу C, запустить её и посмотреть результат/артефакты компиляции. Это подготовительная практика, ещё не ядро IGOR. После неё двигаться к freestanding-сборке и загрузочному проекту небольшими этапами.

## Предварительная дорожная карта
1. Фундамент: CPU, RAM, машинный код, регистры, стек.
2. Инструментарий: C в freestanding-среде, x86 Assembly, compiler/linker, object/ELF.
3. Загрузка: BIOS/UEFI в выбранной конфигурации, bootloader, передача управления.
4. Минимальное ядро IGOR: entry point, linker script, отладочный вывод, сборка/эмуляция.
5. Прерывания и исключения: IDT, IRQ, обработчики.
6. Память: физическая/виртуальная, стек, куча, аллокатор.
7. Устройства и I/O: таймер, клавиатура, диск, драйверная модель.
8. Файловая система.
9. Пользовательские программы, ELF, системные вызовы, user mode.
10. Процессы и планирование.
11. Оболочка и инструменты.
12. Надёжность, тестирование, права, расширяемость; позже — x86-64.
