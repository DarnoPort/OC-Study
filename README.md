# IGOR — OS Development Study

Репозиторий служит внешней памятью и справочником учебного проекта IGOR. Он нужен для продолжения обучения в новых чатах без повторного пересказа.

## Проект

- **Название:** IGOR
- **Назначение:** учебная собственная операционная система, создаваемая параллельно с изучением принципов ОС.
- **Целевая архитектура:** x86, 32-bit.
- **64-bit:** отложено до освоения основ x86.
- **Michael OS:** отдельный предыдущий проект пользователя; использовать как учебный материал и пример для анализа, но не считать целевой ОС обучения.
- **Среда:** ранее пользователь работал с Ubuntu, NASM, GCC, QEMU/эмуляцией и собственной Michael OS. Точный инструментарий IGOR ещё не утверждён.

## Правила обучения

1. Не торопиться. Понимание важнее скорости и количества кода.
2. Идти небольшими уроками: теория → разбор механики → пример → проверка понимания → практика → закрепление.
3. Не выдавать большие листинги без объяснения их назначения.
4. Не считать тему освоенной лишь потому, что её обсудили. Отмечать отдельно «обсуждено» и «подтверждено практикой/объяснением».
5. Если пользователь не знает ответ — спокойно объяснить, без экзаменационного давления и стыда.
6. При ошибках сначала локализовать причину, не предлагать бездумно переписывать проект.
7. Давать точные инструкции по файлам, сборке и проверке, когда начнётся практика.
8. Michael OS можно изучать как референс, но не переносить автоматически её архитектурные решения в IGOR.

## Учебный прогресс

### Урок 0.1 — Первичное представление об ОС и загрузке
**Статус:** начат; базовые идеи частично усвоены, дальнейшее закрепление требуется.

Обсуждено:
- CPU выполняет машинные инструкции и может работать без операционной системы.
- ОС — привилегированное системное ПО, управляющее ресурсами и предоставляющее услуги программам.
- Упрощённая цепочка старта: сброс CPU → прошивка BIOS/UEFI → загрузчик → ядро.
- Загрузчик подготавливает запуск и передаёт управление; ядро — центральная часть работающей ОС.
- Процессор не исполняет исходный C-код напрямую.
- Компилятор переводит C в низкоуровневый код; компоновщик связывает объектные файлы; загрузчик подготавливает запуск ядра.

Проверка понимания:
- Пользователь верно уловил, что CPU может работать без ОС, а ОС — привилегированная программа.
- Пользователь верно различил загрузчик и ядро на базовом уровне.
- Пользователь не знал, почему CPU не может выполнить `kernel.c`; объяснение компиляции дано.
- На вопрос, достаточно ли одной компиляции для запуска ОС, ответил предположительно: «возможно еще чего-то не хватать должно». Разбор компоновки, загрузчика и загрузочного образа дан.

### Урок 0.2 — Машинные инструкции, регистры и выполнение кода
**Статус:** базовое понимание подтверждено ответами; углубление и практика ещё впереди.

Обсуждено:
- Машинные инструкции — команды в кодировке, которую умеет исполнять CPU; исходный C-код процессор напрямую не понимает.
- Регистры — небольшие быстрые хранилища внутри CPU. В качестве примеров рассмотрены EAX, EBX, ECX, EDX, ESP и EBP.
- `mov` записывает/переносит значение; `add` складывает значения, в рассмотренном примере результат сохраняется в первом операнде.
- `EIP` в 32-битном режиме хранит адрес следующей инструкции для исполнения. Это адресный указатель, а не механизм самостоятельного поиска.
- Рассмотрена упрощённая последовательность fetch/decode/execute; отмечено, что современные CPU сложнее этой модели.

Проверка понимания:
- Для `mov eax, 10; mov ebx, 4; add eax, ebx` пользователь верно указал `EAX = 14`, `EBX = 4`.
- Пользователь верно описал последовательное продвижение EIP по инструкциям; уточнено, что EIP хранит адрес, а не сам ищет команду.

**Ещё не закреплено:** машинное кодирование, адресация, флаги, переходы, связь регистров с памятью; реальной практики с ассемблером пока не было.

## Текущая точка остановки

Урок 0.2 пройден на уровне базовой концепции. Не переходить пока к написанию ядра. Следующий небольшой шаг — закрепить связь CPU, регистров и RAM, затем рассмотреть, как меняется ход выполнения через условные переходы.

## Предварительная дорожная карта

Порядок ориентировочный и может меняться по мере обучения.

1. **Фундамент:** CPU, RAM, машинный код, двоичная/шестнадцатеричная система, регистры, стек.
2. **Инструментарий:** C для freestanding-среды, основы x86-ассемблера, компилятор, linker, объектные и ELF-файлы.
3. **Загрузка:** BIOS/UEFI в выбранной конфигурации, bootloader, передача управления ядру.
4. **Минимальное ядро IGOR:** точка входа, linker script, вывод отладочной информации, сборка и запуск в эмуляторе.
5. **Прерывания и исключения:** IDT, IRQ, обработчики.
6. **Память:** физическая/виртуальная память, стек, куча, аллокатор.
7. **Устройства и ввод/вывод:** таймер, клавиатура, дисковый ввод/вывод, драйверная модель.
8. **Файловая система:** чтение/запись, каталоги, устойчивое хранение.
9. **Пользовательские программы:** формат исполняемых файлов, загрузка, системные вызовы, user mode.
10. **Процессы и планирование:** контекст, переключение, изоляция.
11. **Оболочка и инструменты:** команды, диагностика, интерфейс.
12. **Надёжность и развитие:** тестирование, отладка, права доступа, расширяемость; позднее — переход к x86-64.
